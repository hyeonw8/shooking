# 💳 shooking - 결제 모듈 (카드 등록 및 보유 목록)

작성자: hyeon (개인 프로젝트)

## 프로젝트 개요

shooking은 20~30대 젊은 세대를 타깃으로 한 패션 브랜드로,
주력 상품은 신발입니다.

본 결제 모듈은 shooking 쇼핑몰에서 사용자가 상품 구매 시 결제 카드를 선택하고, 신용 카드를 등록 및 관리할 수 있도록 구현한 기능입니다.
상품 목록 페이지 구현 이후 결제 모듈까지 확장하여 결제 UX 흐름을 완성하는 것을 목표로 합니다.

---

### 주요 기능

- **상품 카드에서 결제 단계로 이동**
  - 상품 카드의 `구매` 버튼 클릭 시 `/payments`(보유 카드 목록) 화면으로 이동
  - 상품 탐색 → 결제 단계로 이어지는 사용자 흐름 구성

- **보유 카드 목록 조회 및 결제 카드 선택**
  - 등록된 카드 리스트를 조회
  - 카드 선택 상태를 관리하여 결제 대상 카드 지정
  - 선택된 카드 기준으로 “이 카드로 결제하기” 버튼 활성화

- **카드 추가 기능**
  - `/payments/new` 경로에서 카드 등록 가능
  - 카드 등록 완료 시 보유 카드 목록으로 복귀
  - 복수 카드 등록 가능 구조 설계

## 프로젝트 구조 요약

- **UI / Hook / Validation / State 레이어로 역할을 분리하여 유지보수성을 고려한 구조 설계**
  - 입력 컴포넌트는 제어 컴포넌트 방식으로 구현
  - 카드 등록 폼은 `useAddCardForm` 커스텀 훅으로 입력 상태와 유효성 검증 로직을 분리하여 관리

- **Context + useReducer 기반 결제 상태 관리**
  - `cards`, `selectedCardId` 중심의 상태 구조 설계
  - 카드 추가 및 선택 로직을 reducer로 분리

- **reducer를 순수 함수로 분리하여 테스트 가능한 구조를 확보**

- **입력 값 정제와 표시 로직을 역할별로 분리**
  - 입력 단계에서 값 필터링 및 제한 처리
  - 화면 렌더링 단계에서 포맷 및 마스킹 적용

- **포맷/검증 로직을 유틸 함수로 분리**
  - `cardFormat.js`에서 카드번호/만료일 표시 포맷 관리
  - `paymentValidation.js`에서 카드 등록 입력값 검증 로직 관리

- **단위 테스트 + Storybook 기반 UI 상태 검증**
  - reducer 및 입력 로직 단위 테스트 작성
  - 카드 등록 제출 흐름 테스트 구성
  - 상태별 UI 렌더링 및 상호작용 확인

### **주요 컴포넌트 설명**

#### 1️⃣ 상태 관리 레이어 (shared)

`PaymentsProvider`

결제 모듈 전역 상태 생성 및 Context를 통한 하위 컴포넌트 주입 역할

| 제공 값 | 설명 |
|----------|------|
| `cards`, `selectedCardId` | reducer의 원본 상태 |
| `selectedCard` | `selectedCardId` 기반 계산된 카드 객체 |
| `cardsCount` | 등록된 카드 수 |

- `PaymentsStateContext`, `PaymentsDispatchContext` 분리  
- 상태 조회와 액션 호출 구분  
- `useMemo` 사용, reducer state 변경 시에만 파생 상태 재계산

---

`PaymentsContext` - `PaymentsStateContext` / `PaymentsDispatchContext`  

결제 모듈 전역 상태와 dispatch를 분리하여 제공하는 Context

| Context | 역할 |
|----------|------|
| `PaymentsStateContext` | 상태(`cards`, `selectedCardId`, `selectedCard`, `cardsCount`) 제공 |
| `PaymentsDispatchContext` | reducer `dispatch` 함수 제공 |

- 기본값을 `undefined`로 설정하여 Provider 누락 시 에러 발생하도록 설계  
- 잘못된 Context 접근을 개발 단계에서 조기에 감지하는 목적

---

`PaymentsReducer`  

결제 모듈 전역 상태(`cards`, `selectedCardId`) 관리 reducer

| 액션 | 동작 |
|------|------|
| `ADD_CARD` | 카드 목록 표시용 데이터(`id`, `cardNumber`, `cardOwner`, `expiry`) 추가. 동일한 `id` 존재 시 무시(덮어쓰기 아님). 첫 카드 등록 시 자동 선택 |
| `SELECT_CARD` | `selectedCardId` 변경 |

- 첫 카드 자동 선택은 `state.selectedCardId ?? newCard.id`로 처리, 기존 선택 존재 시 유지  
- 카드 보안 코드(`cvc`)와 비밀번호 앞 2자리(`passwordPrefix`)는 전역 상태에 저장하지 않음  
- `id`가 없는 카드 payload는 무시하는 정책
- 중복 `id`는 덮어쓰지 않고 무시하는 정책

---

`usePayments` - `usePaymentsState` / `usePaymentsDispatch`  

`PaymentsStateContext`, `PaymentsDispatchContext` 접근용 커스텀 훅

| 훅 | 반환 |
|------|------|
| `usePaymentsState` | `PaymentsProvider`가 제공하는 stateValue (`cards`, `selectedCardId`, `selectedCard`, `cardsCount`) |
| `usePaymentsDispatch` | `dispatch` 함수 |

- `PaymentsProvider` 외부 사용 시 에러 throw  
- 잘못된 Context 접근 방지 목적

---

`PaymentsHeader`  

결제 모듈 상단 헤더 UI 컴포넌트. `variant`에 따라 좌측 버튼 구성이 달라지는 구조

| Props | 설명 |
|--------|------|
| `title` | 헤더에 표시할 제목 |
| `variant` | `add`: 뒤로가기 버튼 + 제목 / `list`: 제목만 표시 |
| `onBack` | 뒤로가기 버튼 클릭 핸들러 (`variant="add"`일 때만 노출) |
| `onClose` | 닫기 버튼 클릭 핸들러 |

- 우측 닫기 버튼은 항상 표시  
- 상단 고정(`sticky`) 구조로 스크롤 시에도 헤더 유지

#### 2️⃣ 카드 선택 화면 (MyCardsPage 영역)

`MyCardsPage`  

보유 카드 목록 화면(`/payments`). 등록된 카드 조회 및 카드 추가 화면으로의 이동을 담당하는 페이지 컴포넌트

| 역할 | 설명 |
|------|------|
| 상태 조회 | `usePaymentsState`를 통해 `cards` 조회 |
| 헤더 구성 | `PaymentsHeader`에 `variant="list"` 전달 |
| 조건부 렌더링 | 카드 유무에 따라 빈 상태 UI 또는 카드 목록 UI 표시 |
| 라우팅 처리 | 닫기(`/`) 및 카드 추가(`/payments/new`) 이동 처리 |

- 등록된 카드가 없을 경우 안내 문구와 `AddCardCTA`만 노출  
- 카드가 존재할 경우 `CardList` 렌더링 후 하단에 카드 추가 버튼 배치  
- 실제 결제 로직은 포함하지 않고 목록/이동 책임만 담당하는 구조

---

`CardList`  

보유 카드 목록을 렌더링하는 컴포넌트. 카드 아이템과 결제 버튼을 함께 구성하는 영역

| Props | 설명 |
|--------|------|
| `cards` | 등록된 카드 객체 배열 |

- `CardItem`으로 카드 정보 표시, `PayWithThisCardButton`으로 결제 버튼 구성  
- 현재 `cards[0]`만 렌더링하는 임시 구현 상태  
- 추후 `cards.map` 기반 다중 카드 렌더링으로 확장 예정

---

`CardItem`  

단일 카드 정보를 시각적으로 표현하는 UI 컴포넌트. 카드 번호 마스킹 및 만료일 포맷 처리 포함

| Props | 설명 |
|--------|------|
| `id` | 카드 식별자 |
| `cardNumber` | 전체 카드 번호 (16자리) |
| `cardOwner` | 카드 소유자명 |
| `expiry` | 만료일 4자리 문자열 (MMYY) |

- 카드 번호는 앞 8자리만 노출하고 나머지는 `*`로 마스킹 처리  
- 마스킹된 번호는 4자리 단위로 공백을 삽입하여 가독성 유지  
- 만료일은 `MMYY` 문자열을 `MM / YY` 형태로 변환하여 표시
- `aria-label`에 카드 소유자명 기반 텍스트를 적용하여 접근성 고려

---

`PayWithThisCardButton`  

선택된 카드로 결제를 진행하는 버튼 UI 컴포넌트

| Props | 설명 |
|--------|------|
| `disabled` | 버튼 활성화 여부 제어 |
| `onClick` | 결제 버튼 클릭 핸들러 |

- `disabled` 값에 따라 스타일 및 상호작용 상태 변경  
- 현재는 상위 컴포넌트에서 전달한 `onClick`으로 임시 결제 동작 처리  
- 실제 결제 API 연동 및 선택 카드 정보 전달은 추후 구현 예정

---

`AddCardCTA`  

카드 추가 화면으로 이동하기 위한 CTA 버튼 컴포넌트

| Props | 설명 |
|--------|------|
| `onClick` | 카드 등록 화면으로 이동하는 클릭 핸들러 |

- 플러스 아이콘(`FiPlus`) 기반의 카드 형태 버튼 UI  
- 접근성을 위해 `aria-label="카드 추가"` 속성 제공  
- 카드 목록 화면과 빈 상태 화면에서 공통으로 사용

#### 3️⃣ 카드 등록 화면 (AddCardPage 영역)

`AddCardPage`  

카드 등록 화면(`/payments/new`). 카드 추가 폼을 렌더링하고 상단 헤더의 이동 동작을 담당하는 페이지 컴포넌트

| 역할 | 설명 |
|------|------|
| 헤더 구성 | `PaymentsHeader`에 `variant="add"` 전달 |
| 폼 렌더링 | `AddCardForm` 표시 |
| 라우팅 처리 | 닫기(`/`) 및 뒤로가기(`/payments`) 이동 처리 |

- `variant="add"`를 통해 뒤로가기 버튼 노출  
- 실제 카드 등록 로직은 `AddCardForm`에서 처리하고, 페이지는 레이아웃 및 이동 책임만 담당

---

`AddCardForm`  

카드 등록 입력 및 제출을 담당하는 폼 컴포넌트

| 역할 | 설명 |
|------|------|
| 상태 관리 | `useAddCardForm` 훅을 통해 카드 입력값(`cardNumber`, `cardOwner`, `expiry`, `cvc`, `passwordPrefix`) 상태 관리 |
| 유효성 검증 | `paymentValidation.js` 기반으로 카드 번호, 만료일, 소유자명, CVC, 비밀번호 앞 2자리 형식 검증 |
| 미리보기 반영 | 입력값을 `CardPreview`에 전달하여 실시간 카드 UI 반영 |
| 제출 처리 | 유효성 통과 시 `ADD_CARD` dispatch 후 `/payments` 이동 |

- 만료일은 `MMYY` 4자리 형식이며, 월 범위(01~12) 및 과거 여부 검증 포함  
- 모든 조건을 만족해야 제출 버튼 활성화  
- `isSubmitting`으로 중복 제출 방지 처리  
- 카드 목록 저장은 reducer에 위임하고, 폼은 `useAddCardForm`을 통해 입력·검증 상태를 관리하며 제출 흐름만 담당  
- `cvc`, `passwordPrefix`는 유효성 검증에는 사용하지만 전역 상태에는 저장하지 않음

---

`CardPreview`  

카드 등록 화면에서 입력값을 기반으로 카드 UI를 실시간 미리보기하는 컴포넌트

| Props | 설명 |
|--------|------|
| `cardNumber` | 입력 중인 카드 번호 |
| `cardOwner` | 입력 중인 카드 소유자명 |
| `expiry` | 입력 중인 만료일 (MMYY) |

- `cardFormat.js`를 통해 카드 번호 마스킹 및 만료일 표시 포맷을 공통 처리  
- 카드 번호는 앞 8자리만 노출하고 나머지는 `*`로 마스킹하여 4자리 단위로 표시  
- 만료일은 `MM / YY` 형식으로 표시
- 소유자명이 비어 있을 경우 기본값 `"NAME"` 표시  
- `role="region"` 및 `aria-label` 적용으로 접근성 고려

---

`CardNumberInput`  

카드 번호 입력 UI 컴포넌트  
4칸(각 4자리)으로 분리 입력하며, 숫자만 허용하는 정제 로직과 포커스 이동 UX 처리 포함

| Props | 설명 |
|------|------|
| `value` | 카드번호 원본 값(최대 16자리 숫자 문자열) |
| `onChange` | 카드번호 변경 핸들러(정제된 원본 값 전달) |

- 입력값은 각 칸에서 숫자만 추출하고 4자리로 제한하여 `onChange`로 합친 값 전달  
- 한 칸이 4자리 채워지면 다음 칸으로 자동 포커스 이동  
- Backspace 입력 시 UX 개선 처리 포함  
  - 현재 칸이 비어있으면 이전 칸으로 이동  
  - 현재 칸이 1자리면 해당 칸을 비우고 이전 칸으로 이동  
- 3~4번째 칸은 `type="password"`로 입력값 마스킹 처리

---

`ExpiryInput`  

카드 만료일(MMYY) 입력 컴포넌트  
입력값 정제(숫자만, 최대 4자리)와 표시 포맷(`MM / YY`) 분리 처리

| Props | 설명 |
|------|------|
| `value` | 만료일 원본 값(최대 4자리 숫자 문자열, MMYY) |
| `onChange` | 숫자만 정제된 값 전달 핸들러 |

- 입력 시 숫자만 추출하고 최대 4자리로 제한하여 `onChange`로 전달  
- 표시 값은 `cardFormat.js`의 입력용 만료일 포맷 함수를 통해 처리  
  - 0~2자리: 그대로 표시  
  - 3~4자리: `MM / YY` 형식으로 표시  
- placeholder `"MM / YY"` 제공으로 입력 형식 안내  
- 원본 값과 표시 포맷을 분리하여 제어 컴포넌트 패턴 유지

`CardOwnerInput`  

카드 소유자명 입력 컴포넌트  
입력값 길이 제한, 대문자 변환 및 허용 문자 정제 로직 포함

| Props | 설명 |
|------|------|
| `value` | 카드 소유자명 문자열 |
| `onChange` | 정제된 소유자명 전달 핸들러 |

- 입력값은 최대 30자로 제한  
- 영문은 대문자로 변환 처리  
- 영문 대문자(A-Z), 한글, 공백만 허용하고 그 외 문자는 제거하는 정책  
- 선행 공백 제거(`trimStart`) 처리  
- 현재 입력 길이를 `현재 길이/30` 형태로 표시

`CvcInput`  

카드 보안 코드(CVC/CVV) 입력 컴포넌트  
숫자 정제 및 툴팁 안내 UI 포함

| Props | 설명 |
|------|------|
| `value` | CVC 숫자 문자열(최대 3자리) |
| `onChange` | 숫자만 정제된 값 전달 핸들러 |

- 입력값은 숫자만 추출하고 최대 3자리로 제한  
- `type="password"`로 입력값 마스킹 처리  
- `?` 버튼 클릭 시 툴팁 표시/숨김 토글 상태 관리  
- 툴팁에 CVC 위치 안내 문구 제공  
- `aria-label`, `aria-describedby`, `aria-expanded`를 적용해 접근성 고려

`CardPasswordInput`  

카드 비밀번호 앞 2자리 입력 컴포넌트  
한 자리씩 분리 입력하며 숫자 정제 및 포커스 이동 UX 처리 포함

| Props | 설명 |
|------|------|
| `value` | 카드 비밀번호 앞 2자리 문자열 |
| `onChange` | 두 자리를 합친 값 전달 핸들러 |

- 각 입력 칸은 숫자만 허용하고 1자리로 제한  
- 첫 번째 자리 입력 시 두 번째 칸으로 자동 포커스 이동  
- 두 번째 자리에서 값이 삭제되면 첫 번째 칸으로 포커스 이동  
- 두 자리 이후는 `•`로 표시하여 전체 4자리 구조 표현  
- `type="password"`로 입력값 마스킹 처리

## 테스트 범위

### 1. paymentsReducer 단위 테스트 (`PaymentsReducer.test.js`)

- 초기 상태 반환 검증
- `ADD_CARD` 카드 추가 동작 검증
- `ADD_CARD` 시 첫 카드 자동 선택(`selectedCardId`) 검증
- `ADD_CARD` 중복 id 방지(동일 state 반환) 검증
- `ADD_CARD`에서 `id`가 없으면 기존 state 반환 검증
- `SELECT_CARD` 선택 카드 변경 검증
- `SELECT_CARD`에서 존재하지 않는 id면 기존 state 반환 검증
- 알 수 없는 action 처리 시 기존 state 반환 검증
- 불변성 유지 검증
  - ADD_CARD 성공 시 state와 cards가 새 참조로 생성되는지 확인
  - ADD_CARD 중복 id일 때는 기존 state를 그대로 반환하는지 확인

### 2. ExpiryInput 입력/표시 로직 테스트 (`ExpiryInput.test.jsx`)

- 입력값에서 숫자만 추출하고 최대 4자리까지 `onChange`로 전달되는지 검증
- `value` 길이에 따라 표시 포맷이 올바르게 렌더링되는지 확인
  - 0~2자리: 그대로 표시
  - 3~4자리: `"MM / YY"` 형식으로 표시
- 숫자 외 문자가 섞여도 표시값 포맷이 정상 유지되는지 검증


### 3. AddCardForm 제출 흐름 테스트 (`AddCardForm.test.jsx`)

- 초기 상태에서 제출 버튼이 disabled 상태인지 확인
- 필수 입력값이 채워져 제출 버튼이 활성화되면 submit 시 아래 흐름 검증
  - `dispatch({ type: ADD_CARD, payload })` 호출 여부 확인
  - payload에 카드 목록용 정보(`cardNumber`, `cardOwner`, `expiry`)가 포함되는지 검증
  - `payload.id` 생성 여부 확인
  - `cvc`, `passwordPrefix`가 전역 상태 payload에 포함되지 않는지 검증
  - 등록 후 `/payments`로 이동(`useNavigate`) 호출 여부 확인
- 유효성 조건을 만족하지 못하는 경우 제출이 차단되는지 검증
  - 만료일이 과거인 경우: 제출 버튼 비활성화 + submit해도 dispatch/navigate 미호출
  - 만료월(MM)이 01~12 범위를 벗어나는 경우: 제출 버튼 비활성화 + dispatch 미호출
  - 카드 소유자명이 공백만 있는 경우: 제출 버튼 비활성화 + dispatch 미호출

> 입력 컴포넌트는 mock 처리하여 입력 UI 및 포맷 로직은 제외하고,
> AddCardForm의 제출 로직(dispatch + navigate) 흐름 검증에 집중했습니다.
